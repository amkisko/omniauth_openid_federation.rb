## Dependency

- sqlite3 (was 2.9.6, now 2.10.2)
- Development gemspec floor now `~> 2.0`, `>= 2.10.2`
- Dummy-app and test graph only. The published gem does not require sqlite3 at runtime.

## Symptom

bundler-audit matches sqlite3 2.9.6 against GHSA-4fqr-96q8-xrfx after the advisory database refresh during the Ruby 4.0.10 upgrade pass.

## Evidence

- Advisory: possible SQL query truncation when a string is 4 GiB or larger. Solution: update to `>= 2.10.2`.
- Criticality reported by bundler-audit: Medium.

## Suggested fix

Upgrade lockfiles to sqlite3 2.10.2 and raise the development gemspec floor.

## Trigger

- bundler-audit scanner match while validating the Ruby 4.0.10 upgrade (2026-11-19).

## Assessment target

- CI and test graphs: Gemfile.lock and appraisal locks.
- Published gem runtime: sqlite3 is a development dependency only.

## Advisory

- GHSA-4fqr-96q8-xrfx
- CISA KEV: not checked in this pass.

## Status

- CI and test graphs: fixed after lockfiles pin sqlite3 2.10.2.
- Published gem runtime: not_affected. Component not present in the published gem runtime.

## Applicability

- Vulnerable component present in pre-fix development lockfiles at 2.9.6.
- Exploit conditions require extremely large string values (about 4 GiB). Spec fixtures in this repository do not approach that size.

## Priority

- CI graph: medium because bundler-audit fails while the pin remains.
- Published gem execute path: low. Development-only dependency; exploit size class is unrealistic for this test suite.

## Disposition

- Upgrade. `bundle lock --update=sqlite3` and gemspec floor `>= 2.10.2`.

## Next

- None for sqlite3 after 2.10.2 lands in all appraisal locks.
