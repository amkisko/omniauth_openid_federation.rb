## Dependency

- rack (was 3.2.6, now 3.2.8)
- Transitive via omniauth, oauth2, rack-test, Rails appraisal stacks. Not a direct gemspec runtime dependency.

## Symptom

bundler-audit matches rack 3.2.6 against several advisories (multipart memory DoS, Host allowlist bypass, multipart boundary differentials, Rack::Static path rules).

## Evidence

- bundler-audit solutions require `>= 3.2.8` (or `~> 3.1.23` on older lines).
- Registry latest on the 3.2 line at fix time: 3.2.8.

## Suggested fix

Upgrade every CI lockfile to rack 3.2.8.

## Trigger

- Post Ruby-upgrade bundler-audit queue.

## Assessment target

- Test and appraisal lockfiles; host apps bring their own rack for production.

- GHSA-5v64-555j-wjxm
- GHSA-2j8w-xcrc-x985
- GHSA-p8x9-v4hv-2w4g

## Status

- Lockfile graphs: fixed at 3.2.8.
- Published gem runtime: not_affected for a direct rack pin (hosts supply rack). Transitive omniauth floor now requires rack `>= 2.2.8`.

## Applicability

- Multipart and Rack::Static paths are mostly host middleware. OmniAuth request/callback paths still sit on rack.

## Priority

- High for hosts that terminate HTTP on rack; medium for this library's own test graph.

## Disposition

- Upgrade lockfiles.

## Next

- None for rack after 3.2.8 lands in all appraisal locks.
